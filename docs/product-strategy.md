# Product Strategy

## 产品定位

Open EHR Mobile 是面向企业 HR 数字化、移动端员工自助、申请审批流程演示的开源前端模板。项目中的 EHR 指 Enterprise / Employee HR 场景，不是医疗领域的 openEHR 标准项目。

项目默认保持纯前端 mock，不包含后端服务，不接入真实 HR 数据，也不声明生产环境集成能力。

## 目标用户

1. 前端开发者：需要一个 Vue 3 + Vite + TypeScript 的移动端 HR 模板继续二次开发。
2. HR 数字化产品经理：需要快速演示员工自助、申请、审批和查询路径。
3. 交互和 UI 设计人员：需要一个可运行的移动端业务原型用于评审和迭代。
4. 方案演示团队：需要在无后端条件下演示移动端员工服务体验。

## 核心场景

1. 首页工作台：展示员工身份、待办统计、快捷申请、快捷查询和公告。
2. 流程申请：覆盖证明、推荐奖励、居住证/户籍、考勤异常和离职流程。
3. 审批处理：覆盖待办、已办、我的流程、草稿、审批详情和动作反馈。
4. 员工自助：覆盖个人信息、薪资、考勤、休假、异常撤回、年度结果和联系人。
5. 演示导览：让业务方按推荐路径快速查看关键页面。

## 产品原则

1. 纯前端优先：默认不要求后端即可运行和演示。
2. 演示可信：页面流程、状态反馈和 mock 数据要像真实业务，但不能包含真实数据。
3. 轻量可扩展：保持依赖少、类型清晰、路由稳定，方便二次开发。
4. 移动端友好：优先保障触控、safe area、无横向滚动和核心动作可见。
5. 开源可发布：README、许可、贡献、安全、验证和发布边界清晰。

## 专业运营型设计语言

本项目的移动端 UI 采用“专业运营型”方向，而不是营销落地页、普通后台表单或临时 demo 卡片合集。

1. 首屏先给决策：`/home` 聚合今日待办、流程入口、自助查询和公告；`/approval/todo` 聚合队列、状态、节点和到达时间。
2. 业务状态优先：申请、审批、附件、时间线、表单模式都使用语义色和明确标签表达状态。
3. 移动触控优先：主操作、底部导航、审批动作和表单按钮保持可点击尺寸，避免小字小按钮堆叠。
4. 结构克制：页面区块不再大卡片套小卡片，重复业务项才使用卡片，以减少 demo 感。
5. Mock 透明：关键页面保留 Mock 标识，强调纯前端演示边界。
6. 可验证：所有核心页面必须在 375、390、430 宽度下无横向滚动、无遮挡、无关键 console error。

## 开源路线

1. 文档产品化：完善 README、贡献指南、安全说明、产品策略、架构说明和演示路径。
2. 设计系统产品化：统一 token、图标、按钮、标签、列表、表单和反馈状态。
3. 核心体验优化：首页、壳层、底部导航和核心业务入口先于细节页面。
4. 业务域深化：逐步完善申请、审批、自助三大域的状态、空列表、错误提示和 mock 行为。
5. 质量门禁：扩展 smoke、多视口截图、console error、横向滚动和发布前检查。

## 非目标

1. 不提供默认后端服务。
2. 不提供真实身份认证。
3. 不承载真实员工或组织数据。
4. 不作为医疗 openEHR 标准实现。
5. 不默认引入大型 UI 组件库。
